# GEO Pass — обязательные правила разработки

Применяется ко всем новым и изменяемым файлам `geo-pass/`. **Канонический документ** с уже утверждёнными решениями: закрытый `AnnaTrocka306/Octopus/docs/GEO_PASS_MANDATORY_RULES.md`. Перед изменениями читать его и соответствующие решения из `Octopus/docs/`, затем сверять с рабочей карточкой существующей профессии.

1. Без самовольных вопросов, функций, путей, дополнительных платных вызовов или изменений ранее утверждённого интерфейса. Область задачи сначала сопоставить с принятыми решениями.
2. В утверждённых карточках **направлений деятельности** — 1–3 чекбокса с счётчиком и «Другое» в общей квоте, пояснение о возможности добавления направлений **на втором этапе регистрации**, сохранение отметок и их показ в предпросмотре. Отдельные карточки выбора регулируемой профессии / основной сферы не превращать автоматически в множественный выбор.
3. Новые / редактируемые названия профессий — естественные гендерно-нейтральные на DE/RU/EN. Ранее утверждённые формулировки без отдельного разрешения не переписывать.
4. Первый этап регистрации остаётся коротким; специализации второго этапа без отдельного разрешения не добавлять. Не утверждать, что отключённые генерация AI, email и реальная публикация работают.
5. Публичный клиентский UI и приватные ответы разделены. Не менять оригинальный `geo-pass/assets/octopus-cta.webp`, не отправлять реальные данные в тестовую систему.
6. **Перед загрузкой**: выполнить `for file in geo-pass/assets/*.js; do node --check "$file"; done` и `node --test geo-pass/tests/mandatory-regression.test.cjs`. При провале нельзя коммитить, пропускать тест или ослаблять его без разрешения.
7. **После загрузки**: проверить результат GitHub Actions и наличие обновлений на целевой ветке. Отдельно проверить телефонный браузер и полный маршрут назад/вперёд; если браузерная проверка невозможна, явно отметить это.
8. Workflow `.github/workflows/geo-pass-mandatory-regression.yml` запускается на push/PR рабочей ветки. Он **не блокирует автоматически прямые записи через GitHub API**. Для принудительного запрета merge при красном статусе отдельно потребуется required status check / protection rule.

Регрессионные тесты: `geo-pass/tests/mandatory-regression.test.cjs`. Это проверка конкретных сценариев, не разрешение менять все существующие формы ради единообразия.
